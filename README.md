# Polymarket 5-Minute Up/Down Bot

Экспериментальный бот для торговли **5-минутными** Up/Down рынками на
Polymarket по 6 активам (BTC, ETH, SOL, BNB, HYPE, XRP) параллельно — 6
независимых потоков. Это **форк** основного 15-минутного бота — та же
кодовая база, стратегия и весь риск-менеджмент, но специально урезанная
до одного таймфрейма: 15-минутные и часовые профили физически удалены
(не просто выключены), чтобы держать этот проект узким и понятным.

**⚠️ Параметры для 5-минутного таймфрейма — НЕПРОВЕРЕННЫЕ ДОГАДКИ.**
Основной 15-минутный бот откалиброван на 961 реальной сделке другого
трейдера плюс на живых 4-часовых отчётах за несколько дней реальной
торговли. Для 5-минутного рынка такой калибровки не делали — параметры
в `src/timeframes.py` просто пропорционально пересчитаны (короче период
ATR/EMA, уже окно входа) из того, что сработало на 15-минутке. Держи
бота в `DRY_RUN=true` и присматривайся к первым отчётам особенно
внимательно — вполне возможно, что для 5-минутного рынка потребуется
другая настройка.

**⚠️ Это торговый бот с реальными деньгами** (когда `DRY_RUN=false`).
Рынки Up/Down устроены как бинарные ставки: выигрыш ограничен ценой
входа, а проигрыш — это полная потеря ставки. Даже "безопасный" вход по
0.90 означает, что в среднем на дистанции нужен винрейт выше ~90%, просто
чтобы выйти в ноль после комиссий и проскальзывания.

## Чем 5-минутный рынок отличается от 15-минутного

- **Слаг рынка** — тот же формат, что у 15m: `{asset}-updown-5m-<unix_ts>`,
  детерминированно вычисляется по чистой UTC-сетке (в отличие от часовых
  рынков, которые привязаны к Eastern Time и в этом проекте не
  реализованы вообще).
- **Индикаторы короче**: ATR(7)/EMA(3,7) на 1-минутных свечах вместо
  ATR(14)/EMA(9,21) — пропорционально более быстрому рынку.
- **Окно входа уже**: по умолчанию 1.0–4.5 минуты из 5 (вместо 2–9 из 15);
  меняется кнопкой в ⚙️ Настройках (см. «Окно входа и паузы без сделок»).
- **Опрос чаще**: раз в 3 секунды вместо 5 — рынок живёт втрое меньше,
  нужна более частая проверка.
- Всё остальное — safety score (distance/trend/volatility/time/liquidity
  с MACD как третьим голосом за тренд), жёсткие условия по времени/
  дистанции/волатильности, стоп-лоссы, отчёты, слежка за кошельком —
  без изменений, тот же механизм, что и в 15-минутном боте.

## Как это работает (кратко)

1. Определяем активный 5-минутный рынок по каждому активу.
2. Считаем ATR(7), EMA(3/7), MACD(12/26/9) на 1m-свечах Binance.
3. Safety score (0–100) из пяти факторов; вход требует одновременно:
   цена в диапазоне `[MIN_ENTRY_PRICE, MAX_ENTRY_PRICE]`, score выше
   порога, время внутри окна, дистанция выше минимума, волатильность не
   аномальная — все четыре последних условия жёсткие, не просто вклад в
   сумму (это исправленный баг из истории 15-минутного бота: раньше
   сильный сигнал по одному фактору мог перевесить полный провал по
   другому).
4. Вход — market BUY с исполнением FOK, с проверкой реальной глубины
   стакана перед отправкой.
5. Резолюция — общая фоновая задача сверяется с Gamma API, шлёт итог в
   Telegram.

## Установка

```bash
git clone <твой-репозиторий>
cd polymarket-5m-bot
python3 -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

Заполни `.env`:
- `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` — **обязательно ДРУГОЙ бот**,
  не тот же токен, что у основного 15-минутного бота (Telegram не даёт
  опрашивать один токен из двух процессов одновременно). Новый бот — через
  [@BotFather](https://t.me/BotFather).
- `POLY_PRIVATE_KEY` — только когда будешь готов к LIVE; для DRY_RUN не
  обязателен.
- `WALLET_TRACK_ADDRESS` — по умолчанию тот же адрес, что отслеживает
  основной бот. Он торгует 15-минутные рынки, так что уведомления о нём
  здесь будут не по теме этого проекта — можно выключить кнопкой
  🐋 Слежка за кошельком → 🔔 Уведомления в `/menu`, если не нужно.

## Управление из Telegram

Те же кнопки, что у основного бота: старт/стоп, активы, размер позиции
(фикс или % от банка), стоп-лосс/день, стоп-лосс позиции, диапазон входа,

## Режим по монетам: LIVE и DRY одновременно

В 🪙 Активах у каждой монеты три кнопки: включить/выключить поток, режим
🔴 LIVE / 🧪 DRY и ⚙️ — свои настройки монеты (см. следующий раздел).
Реальные ордера идут только по монетам в LIVE (и только когда сам бот в LIVE);
остальные включённые монеты торгуют виртуально — те же сигналы и правила
входа, но без денег. Так можно держать BTC в реальной торговле и параллельно
проверять ETH, SOL, XRP, BNB, DOGE, HYPE.

- **Два переключателя.** 🔴 LIVE у монеты только выбирает, какие монеты
  торгуют на реальные деньги. Сами реальные сделки начинаются после общей
  кнопки «🔴 Включить LIVE» внизу главного меню. Пока бот в DRY RUN, у таких
  монет на кнопке «🔴 LIVE ⏳», а в главном меню и в 🪙 Активах — подсказка.
  Окно подтверждения общего LIVE показывает, по каким монетам и с какой
  ставкой пойдут реальные ордера.
- Новые монеты всегда начинают с DRY. Перевод в LIVE — с подтверждением.
- Виртуальные сделки не занимают место реальных (лимит позиций считает
  только реальные, и только в ещё идущих рынках) и не влияют на дневной стоп-лосс — он считается
  только по реальным сделкам.
- Уведомления о сделках DRY-монет по умолчанию выключены (кнопка
  «🔕 Уведомления DRY-монет»), чтобы не засыпать чат; монеты в LIVE
  уведомляют как раньше.
- В 📊 Статистике и в подписи к 4-часовому отчёту реальные и виртуальные
  сделки показаны раздельно, по каждой монете — «проигрышей фактически /
  ожидалось по ценам входа». Монету имеет смысл переводить в LIVE, только когда
  там будет «заметно реже, чем заложено в цены».
- Каждый тик по каждой включённой монете пишется в signals.csv отчёта: по нему
  можно подобрать порог score и диапазон цены отдельно для каждой монеты.
- DOGE добавлен в список монет. Если в переменных окружения задан `ASSETS`,
  допиши туда `doge` (или удали переменную — по умолчанию
  `btc,eth,sol,xrp,bnb,doge,hype`).

## Свои настройки монеты: диапазон входа и ставка

Кнопка ⚙️ в строке монеты (🪙 Активы) открывает её настройки:

- **📈 Диапазон входа** — минимум и максимум ask, при которых бот входит по
  этой монете (пресеты, ±0.01 или своё число; можно в центах: `92` = 0.92).
  Максимум — это и потолок цены ордера. Выше `MAX_ENTRY_EXECUTION_PRICE`
  (0.97) поставить нельзя ни у монеты, ни в общем диапазоне: дороже бот не
  покупает, и в DRY такие «сделки» были бы по цене, которой в стакане нет.
- **💰 Ставка** — свой режим: % от банка или фиксированная сумма, каждый со
  своим значением. Банк для режима % один на все монеты (кошелёк один):
  стартовый банк + реализованный PnL реальных сделок; стартовый банк задаётся
  в 💰 Размер позиции главного меню. У DRY-монеты ставка влияет только на
  виртуальный PnL.

Пока у монеты нет своих значений, она берёт общие из главного меню и
меняется вместе с ними. Первое изменение в ⚙️ копирует текущие общие
значения, дальше монета живёт отдельно; «↩️ Как в общих» возвращает её к
общим. Монеты со своими настройками помечены «⚙️ свои», а сами настройки
видны в главном меню, в 🪙 Активах и в подписи к 4-часовому отчёту.

Дневной стоп-лосс, лимит открытых позиций, порог score и масштабирование
ставки по score — общие для всех монет. Всё хранится в базе (`bot_settings`,
ключ `asset_overrides`) и переживает рестарт — если подключён постоянный том.

В trades.csv (отчёт и /export) добавлены колонки: `signal_ask` — ask на
сигнале (`entry_price` — это потолок ордера), `safety_score`, `range_min`,
`range_max` — диапазон монеты в момент входа. По ним видно, какие сделки
сделаны при каких настройках.

## Окно входа и паузы без сделок

**Почему бот иногда молчит часами.** Отчёты 06–08.10 (7 монет, каждый тик):
11 часов 07.10 и почти 7 часов 08.10 без сделок — при этом бот работал без
перебоев. Из 1344 рынков в эти часы сигнал был только в двух: в окне входа
цена почти всегда была ближе 1.5 ATR к страйку (50% рынков) или score не
дотягивал до порога (35%). В активные часы ATR больше, и нужный отрыв от
страйка бывает редко. У одного BTC по истории пауза 4–8 ч бывала примерно
раз в день. Порог score, диапазон цены и порог в ATR на истории не дают
устойчивого выигрыша: что помогает в одной половине данных, не помогает в
другой.

**⏱ Окно входа** (⚙️ Настройки): за сколько минут до конца рынка можно
входить. Раньше было зашито 1.0–3.5 (пропорция от 15m, на 5m не
проверялось). Теперь по умолчанию 1.0–4.5:
- история BTC 25.09–06.10 (2447 рынков): 28 входов в день вместо 23,
  прибыль на ту же ставку +40%, лучше в 9 днях из 11; добавочные входы —
  2 проигрыша при 5.2 ожидаемых;
- новые данные 06–08.10 (7 монет, в подборе не участвовали): 96 входов
  вместо 62; добавочные 42 входа — без проигрышей при 2.7 ожидаемых.
При первом запуске этой версии окно 1.0–3.5 само меняется на 1.0–4.5,
остальные настройки не трогаются. Вернуть можно кнопкой. Переменные
`TF_5M_MIN_MINUTES_LEFT` / `TF_5M_MAX_MINUTES_LEFT` теперь задают только
значение для новой базы.

**📦 Реальных позиций одновременно** (⚙️ Настройки, 2/3/4/6; по умолчанию
`MAX_OPEN_POSITIONS`). Считаются только позиции в ещё идущих рынках: после
конца рынка исход уже не меняется, а раньше слот держался, пока Gamma API не
отметит рынок закрытым — несколько минут, и сигналы других монет в это время
пропускались (похоже, так 07.10 в 05:07 UTC пропали входы ETH и BTC). Монеты
двигаются вместе, поэтому больше позиций — больше проигрышей разом.

**Ликвидность до потолка цены.** Перед FOK-ордером бот теперь считает объём
только по уровням стакана не дороже потолка ордера. Раньше в расчёт шли все
10 уровней, и на тонких стаканах (DOGE, HYPE) или на сигнале по 0.95 ордер
на полную ставку отменялся целиком. Теперь ставка урезается до того, что
реально есть по этой цене.

**🔎 Почему нет сделок** (кнопка в главном меню): за последние 4 часа —
сколько рынков бот смотрел, в скольких был сигнал, что мешало сигналу
(расстояние до страйка, score, цена вне диапазона, волатильность) и какие
сигналы не стали сделками и почему (лимит позиций, дневной стоп, мало
ликвидности, ошибка ордера с текстом ошибки, пауза). Те же две строки — в
подписи к 4-часовому отчёту (счётчик пропусков обнуляется с каждым отчётом).

## Если после деплоя всё сбросилось

Если при старте бот пишет «⚠️ База данных создана заново», а он уже работал
раньше, значит база не сохраняется между деплоями. Тогда при каждом деплое
режим возвращается в DRY RUN, ставка, банк и свои настройки монет — к
значениям по умолчанию, статистика обнуляется. Подключи в Coolify постоянный
том (Persistent Storage) на `/app/data` и заново выставь настройки.

## Проигрыши: что показали отчёты 18.09–06.10

Разбор всех 4-часовых отчётов: 2491 рынок BTC 5m у этого бота и 235 у
Chainlink-версии. Реальных сделок Binance-бота 213
(после деплоя 01.10 — все 127, без пропусков). Проигрышей 9: −21.86, −27.11,
−69.34, −36.65, −35.26, −50.04, −45.62, −41.27, −39.87; по ценам входа
ожидалось ≈13.9. Итог по всем 213 сделкам +$113.57.

- **Цена честная.** Без фильтра входы по 0.90–0.95 за 1–3.5 минуты до конца
  проигрывают ровно столько, сколько заложено в цену (171 проигрыш на 2039
  входов при ожидаемых 174). Вход по 0.95 — примерно 1 проигрыш на 20
  сделок, и один проигрыш съедает 15–20 выигрышей.
- **Фильтр score ≥ 88 проигрывает примерно на треть реже, чем заложено в
  цены:** 9 из 242 виртуальных входов при ожидаемых 17.4. На днях после
  подбора порога — 7 из 148 при ожидаемых 10.6: направление то же, но пока
  это может быть случайностью. Порог 75 преимущества не даёт.
- **Проигрыш заранее не распознать.** 31 признак (рывок цены перед входом,
  ATR, расстояние в $ и в ATR, время, тренд, стакан, число пересечений
  страйка, «нервность» последних рынков, время суток…) — ни один надёжно не
  отделяет проигрыши. 7 из 9 проигрышей пришлись на тихий рынок (ATR ≤ $9,
  до страйка всего $16–33), но там же и половина выигрышей, и проигрышей
  там всё равно меньше, чем заложено в цены.
- **Стакан Polymarket быстрее наших цен.** Изменение стакана предсказывает
  будущую цену Binance/Chainlink на ~3 с вперёд, наоборот — нет. Выходить
  «по Binance» поздно: рынок уже переоценил позицию.
- **Стоп-лосс прибыль не увеличивает.** Проигрышная позиция падает с 0.9 до
  0.4 за секунды, а примерно 4 из 10 позиций, просевших на 50%, потом всё
  равно выигрывают. На всех 213 реальных сделках стоп 50% дал бы +$66 вместо
  +$114 (продал бы 8 сделок, которые потом выиграли). Тейк-профит 0.97–0.99
  и выход по пересечению страйка — тоже хуже, чем держать до конца. Стоп
  позиции по умолчанию выключен (если включить — проверяется раз в ~2 с).
- **Отчёт раньше не показывал исход сделки, открытой в конце окна:**
  проигрыш 03.10 04:42 (−36.65) не попал ни в один отчёт. Теперь trades.csv
  захватывает и последние 15 минут прошлого окна (уже с исходом; повторы
  отличаются по id), а команда /export присылает все сделки одним CSV.

Вывод: размер проигрыша регулируется размером ставки (💰 Размер позиции), а
не стопом и не фильтрами. В 📊 Статистике есть счётчик «проигрышей фактически
/ ожидалось по ценам входа»: если фактических станет заметно больше
ожидаемых, преимущество пропало и бота пора останавливать.

## Хедж-бот (hedge_bot.py) — торгует по итогам анализа momentum-данных

В отличие от momentum_tracker (только наблюдает) — этот модуль реально
торгует, параллельно с основной стратегией: вход по `hedge_entry_price`
(0.70), докупка противоположной стороны при `hedge_trigger_price` (0.90)
в таком количестве акций, чтобы выплата была фиксирована независимо от
исхода. Если цена не доходит до порога хеджа — остаётся односторонняя
позиция (по данным на 2026-09-20 такие случаи почти всегда проигрывают,
~4.5% винрейт — известный риск, не баг).

Порог 0.90 выбран по бэктесту на реальных momentum-отчётах (не наугад):
хедж позже даёт бОльшую гарантированную маржу за сделку, что перевешивает
рост числа незахеджированных случаев. Управление — кнопка "🔒 Хедж-бот" в
`/menu`. PnL в отчётах (`*_hedge.csv`) — без учёта комиссии тейкера.

## Исследовательский модуль: контрольные точки цены (momentum_tracker)

Отдельно от торговли — `src/momentum_tracker.py` НЕ покупает и не
продаёт, только наблюдает. Отслеживает более дорогую сторону каждого
активного рынка и, как только её цена входит в диапазон 0.70-0.95,
логирует полный снимок (RSI, MACD, ATR, EMA, полосы Боллинджера, объём,
дисбаланс стакана) при каждой пройденной контрольной точке (шаг 0.05).
После резолюции рынка каждая запись помечается итоговым исходом. Раз в
`REPORT_INTERVAL_HOURS` — отдельный `*_momentum.csv` в Telegram.
Включается/выключается через `MOMENTUM_TRACKER_ENABLED` в `.env`.

Идея (проверяем на данных, не сразу торгуем): если цена стороны надёжно
проходит путь 0.70→0.80 внутри одного окна, можно купить по 0.70,
дождаться роста, докупить противоположную сторону подешевевшей и
зафиксировать прибыль независимо от исхода — но комиссия тейкера на
каждую ногу (7% для крипто-рынков) съедает часть маржи, это тоже нужно
учитывать при оценке реальной выгоды.

## Дальнейшая калибровка

Как и с 15-минутным ботом — присылай 4-часовые отчёты (CSV с сигналами и
сделками) для разбора. Методика та же: смотрим реальный винрейт против
подразумеваемого ценой, ищем, какие компоненты score реально предсказывают
исход именно на 5-минутном рынке (может оказаться, что здесь работает
иначе, чем на 15-минутном — не переноси выводы 1-в-1 без проверки).
